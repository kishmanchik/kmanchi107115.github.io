02How I work

Three principles that show up in everything below.

Deterministic first, model second

An LLM is a leaf, not a controller. Rules, graphs and known-issue registries resolve the common cases with zero model calls — cheaper, instant and reproducible. The model handles only what's genuinely novel.

  • In production this meant ~80% of failures resolved with zero or one model call.
  • Deterministic paths are also testable, which is what makes the whole system auditable.

Safety as an artifact, not a policy

"We won't do X" is a comment. A check that fails the build is an engineering control. I make dangerous states unreachable by construction and then prove it in CI.

  • A write-capable tool that does not exist in the process unless explicitly enabled at startup.
  • An output guard that withholds destructive commands a model proposes.
  • A redaction layer proven byte-identical across two languages against a golden corpus — including a negative case that fails on over-scrubbing.

Velocity is only safe if machines check it

I build with AI-agent orchestration — parallel subagents, reusable skills, isolated worktrees — which produces a lot of code quickly. The engineering that matters is refusing to trust it.

  • Evaluation harnesses with pinned baselines that fail releases on regression.
  • Determinism tests with network egress jailed, so nothing can silently call a model.
  • A linter that fails the build when a repository contradicts its own documentation.

Argus — AI-assisted application security platform internal project

sole author · Python · TypeScript/React · Kotlin · ~375K LOC · 16.4K tests

A security-analysis platform that runs a large fleet of scanner adapters and applies a language-model layer for vulnerability chaining, severity classification, false-positive triage and remediation — while keeping deduplication deliberately deterministic so results stay reproducible.

  • 32 scanner adapters across SAST, SCA, secrets, IaC and container analysis.
  • Four delivery modes — CLI, REST API, an MCP server for agent integration, and CI/CD plugins.
  • Releases gated by an evaluation harness with a pinned recall / false-positive baseline.
  • Proposed fixes are emitted as diffs and re-scanned in a sandbox before being surfaced.
  • Exploit-likelihood enrichment; standards-compliant SARIF output; web UI and IDE extensions.

Safe agentic AI for production Kubernetes internal project

sole author of the substrate and 6 of 7 servers · Go + Python · ~32K LOC · 509 tests

A fleet of read-only-first MCP servers that let an AI agent diagnose live Kubernetes, cloud and workflow problems without being able to damage them. I wrote the shared substrate, the cross-language conformance harness and every CI gate; a colleague later built a seventh server on the framework.

  • 60 tools — 59 read-only, 1 write, and the write tool is absent from the process unless explicitly enabled. A CI check boots every server over JSON-RPC and asserts the registry.
  • Default-deny cluster-context guard: fail-closed, non-production only, enforced at every entry point.
  • Prompt-injection defence — untrusted cluster output is normalised, structurally fenced, and the model is told so at handshake time.
  • Zero-model-call determinism asserted in CI with network egress jailed.
Both systems were built for internal use and dogfooded against real production services. Source and internal architecture detail are proprietary and deliberately not published here — happy to walk through design decisions in conversation.
